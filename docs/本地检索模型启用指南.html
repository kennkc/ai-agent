本地检索模型启用指南（BGE-M3 / bge-reranker）¶

适用：LLM 走 API、检索用本地模型的部署形态（2026-09-20 决策） 权重位置：E:\ai_workspace\project_space\模型权重\ 状态：权重已下载完成，运行时库尚未安装（因此当前仍走确定性降级后端）

1. 为什么需要本地检索模型¶

系统里有两个"模型"，职责完全不同，不要混淆：

大语言模型（LLM） 检索模型（本项目要本地跑的）
例子 DeepSeek-V3 / GPT-4o / Qwen-Max BGE-M3（嵌入）、bge-reranker-v2-m3（重排）
作用 生成回答文本 把文本转成向量、给候选排序
规模 数十亿~数千亿参数 约 5.68 亿参数
部署方式 走 API 接口（WB-10 前台配置） 本地（本指南）

为什么检索不放 API：检索是每次提问都要做的高频操作，本地跑零调用成本、低延迟、数据不出境。

当前降级状态（未装运行时库时）：

环节 降级后端 差异
嵌入 字符 n-gram 哈希（768 维） 靠字面重叠，不是语义相似 —— 问"如何提高团队协作"检索不到"改善跨职能配合"
重排 词法覆盖率打分 非交叉编码精排

两者都会如实上报 degraded=true（DEBT-010 / DEBT-011），不伪造质量。

3. 启用步骤¶

步骤 1 · 安装运行时库（必需，约 2-3 GB）¶

cd services\python\nlp-service
.\.venv\Scripts\python.exe -m pip install sentence-transformers

该库会连带安装 PyTorch（CPU 版约 2.5 GB）。代码用 find_spec("sentence_transformers") 探测， 未安装时自动走降级后端，所以这一步不做也不影响系统运行。

步骤 1.1 · ⚠ torch 版本硬约束（2026-09-20 实测，踩了两轮）¶

约束 原因
torch >= 2.6 transformers（4.5x 与 5.x 均如此）为修复 CVE-2025-32434 强制要求；低于此版本加载 .bin 权重直接抛 ValueError ... require users to upgrade torch to at least v2.6
torch <= 2.7 torch ≥2.8 在 Python 3.10 上 DLL 初始化失败（OSError: [WinError 1114] ... c10.dll）

结论与推荐：

  • Python 3.10 环境（本机现状）：必须锁定 torch>=2.6,<2.8，实测 2.7.1+cpu 可用 powershell .\.venv\Scripts\python.exe -m pip install "torch>=2.6,<2.8" sentence-transformers
  • Python 3.12 环境（与 CI 一致）：无上述上限，可直接装最新 torch —— 推荐升级到 3.12 以消除该约束

另一个相关坑：只有 pytorch_model.bin 的模型会走 torch.load 从而触发版本检查； safetensors 格式不受影响（错误信息明确写了）。本项目 reranker 是 safetensors； BGE-M3 官方仓库只有 .bin（ModelScope 与 hf-mirror 均无 safetensors，实测 HTTP 404）。

本机实测结果（torch 2.7.1+cpu）：

Embedding: backend=bge-m3            dim=1024  degraded=False
Reranker : backend=bge-reranker-v2-m3          degraded=False

步骤 4 · 全量重索引（切换的必要代价，不可跳过）¶

向量维度会从 768 → 1024，Qdrant 集合必须重建：

# 1) 停 body-service
# 2) 删除旧集合（维度不兼容）
# 3) 重启服务，让它按新维度建集合
# 4) 重新灌入全部知识（旧向量不可复用）

为什么不能省：新旧向量混存会导致检索结果错乱（不同维度/不同语义空间无法比较）， 而且这种错误不会报错，只会让召回质量静默下降。
