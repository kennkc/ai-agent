## 1. 为什么需要本地检索模型

系统里有两个"模型"，职责完全不同，不要混淆：

| | 大语言模型（LLM） | 检索模型（本项目要本地跑的） |
|---|---|---|
| 例子 | DeepSeek-V3 / GPT-4o / Qwen-Max | **BGE-M3**（嵌入）、**bge-reranker-v2-m3**（重排） |
| 作用 | 生成回答文本 | 把文本转成向量、给候选排序 |
| 规模 | 数十亿~数千亿参数 | 约 5.68 亿参数 |
| 部署方式 | **走 API 接口**（WB-10 前台配置） | **本地**（本指南） |

**为什么检索不放 API**：检索是每次提问都要做的高频操作，本地跑零调用成本、低延迟、数据不出境。

**当前降级状态**（未装运行时库时）：

| 环节 | 降级后端 | 差异 |
|---|---|---|
| 嵌入 | 字符 n-gram 哈希（768 维） | **靠字面重叠**，不是语义相似 —— 问"如何提高团队协作"检索不到"改善跨职能配合" |
| 重排 | 词法覆盖率打分 | 非交叉编码精排 |

两者都会如实上报 `degraded=true`（DEBT-010 / DEBT-011），**不伪造质量**。

## 3. 启用步骤

### 步骤 1 · 安装运行时库（**必需**，约 2-3 GB）

```powershell
cd services\python\nlp-service
.\.venv\Scripts\python.exe -m pip install sentence-transformers
```

> 该库会连带安装 PyTorch（CPU 版约 2.5 GB）。代码用 `find_spec("sentence_transformers")` 探测，
> **未安装时自动走降级后端**，所以这一步不做也不影响系统运行。

### 步骤 2 · 指向本地权重（**必需**）

代码已支持环境变量覆盖（本指南配套改造）：

```powershell
$env:EMBEDDING_MODEL_PATH  = "E:/ai_workspace/project_space/模型权重/bge-m3"
$env:RERANKER_MODEL_PATH   = "E:/ai_workspace/project_space/模型权重/bge-reranker-v2-m3"
```

不设这两个变量时，默认仍按 HF 模型名（`BAAI/bge-m3`）联网加载 —— 内网环境必须设置。

### 步骤 3 · 验证加载

```powershell
cd services\python\nlp-service
.\.venv\Scripts\python.exe -c "from app.embedding import EmbeddingService as E; s=E(); print(s.status())"
```

期望：`degraded=False`，`dim=1024`，`engine` 为 BGE-M3。
（若仍显示 hash 后端，检查 `EMBEDDING_MODEL_PATH` 是否正确、sentence-transformers 是否装好。）

### 步骤 4 · **全量重索引**（切换的必要代价，不可跳过）

向量维度会从 **768 → 1024**，Qdrant 集合必须重建：

```bash
# 1) 停 body-service
# 2) 删除旧集合（维度不兼容）
# 3) 重启服务，让它按新维度建集合
# 4) 重新灌入全部知识（旧向量不可复用）
```

**为什么不能省**：新旧向量混存会导致检索结果错乱（不同维度/不同语义空间无法比较），
而且这种错误**不会报错**，只会让召回质量静默下降。

### 步骤 5 · 评测回归

- 跑 Phase 3 已登记的评测集，对比切换前后的召回命中率与排序质量
- 人工抽查 10-20 个**语义相近但用词不同**的问题（这正是本次切换要改善的场景）
- 结果记入 `docs/优化日志/`，并更新《技术债台账》DEBT-010/011 状态

## 4. 回滚

| 场景 | 动作 |
|---|---|
| 加载失败 / 内存不足 | 取消两个环境变量（回到 HF 名称）或卸载 sentence-transformers → 自动降级回 hash 后端 |
| 重索引中途失败 | 保留旧集合快照；恢复后重新灌入 |
| 质量不升反降 | 同上回滚；把评测对比结果记为"切换未达标"而不是悄悄回退 |
