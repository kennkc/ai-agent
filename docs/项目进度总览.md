## 一、当前状态一句话

**Phase 0 / 1 / 2 已全部交付并验收**，项目当前停在 **Phase 2 之后的「工程化加固期」**：
不新增阶段能力，而是把已有能力做**真实、可验证、可交付**（观测区接真数据、契约与实现对齐、
控制面加鉴权、数据源降级可见）。**Phase 3+ 处于冻结状态**（团队在固化 Phase 0-2 资产）。

唯一未闭合的验收项是 **OCR 端到端**，阻塞原因是需要外部引擎（PaddleOCR / Tesseract）尚未安装 ——
系统对此**诚实上报** `available=false`，不伪造结果。

**约定**：三支保持内容一致 —— 任一分支的改动，收口时 `git merge --ff-only` 同步到另两支；
```
git push origin codex/main
git push origin codex/main:dev
git push origin codex/main:workbuddy/main
```
跨分支吸收按「**时间 + 语义**逐项合并」，**禁止整文件覆盖**。

### 5.2 远端地址（**两台机器不同，别照抄**）

| 机器 | remote | fetch | push |
|---|---|---|---|
| 另一台开发机（README §8.4.1 记录） | `origin` | 本地镜像仓库 `<repo>\ai-agent`（快） | `git@github.com:kennkc/ai-agent.git`（直达） |
| **本机（WorkBuddy 侧）** | `origin` | `git@github.com:kennkc/ai-agent.git`（SSH 直达） | 同左 |

> 本机原走 HTTPS，443 曾长期被阻断 → 现统一走 **SSH(22)**。
> `README.md` §8.4.1 描述的是**另一台开发机**的中转拓扑，本机是直连，两者不要混用。

### 5.3 变更前置约定（强制）

任何仓库内容变更之前，先执行 **`README.md` §8.0**：`git fetch` → 判落后/领先 → **解读**对方改动
→ 再决定集成 → 才开工。已登记为技能 `git-sync-before-change`
（WorkBuddy 侧 `~/.workbuddy/skills/`、Codex 侧 `~/.agents/skills/`，两份必须保持一致）。
