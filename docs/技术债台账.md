## 二、逐条详情

### DEBT-001 · body-service 检索为内存实现 —— 已闭合 ✅

- **原简化实现**：`BodyStore` 用 `ConcurrentHashMap<String, List<StoredChunk>>` 按租户存切片；
  检索打分是「整串包含 = 1.0，否则按查询字符在正文中的命中率」——**纯内存、无持久化、无语义相似度**。
- **正式目标**：Qdrant 向量检索。`docker-compose.yml` 已定义 qdrant 服务（端口 6333/6334），
  但**当时没有任何服务调用它**。
- **当前实况（Phase 3，2026-09-18）**：body-service **整体重写**为持久化知识管道：
  - 冷层真相源 `PgMetadataStore`（PostgreSQL）· 温层向量 `QdrantClient`（集合 `lifeform_knowledge`）·
    热层缓存 `HotCacheStore`（Redis，租户前缀指纹）；
  - 统一门面 `StorageFacade` + 热度分层 `TierRouter`（阈值可配）；
  - 入库 `IngestService`（分块 → 嵌入 → 向量入库）、检索 `RetrievalService`（缓存优先 → 向量召回 → 重排）、
    `RagPipeline`（检索增强生成）；
  - **旧的 `BodyStore` / `BodyController` / `BodyStoreTest` 已删除**（被取代即销项）。
- **关闭依据**：端到端实测——文档入库后可被语义检索命中（语义相近可召回，非字符匹配），
  检索 P99 **366ms**（< 500ms 验收）、命中率 0.925、缓存命中率 0.45；租户隔离生效；
  重入库幂等、删除无孤儿向量。验收脚本 35 项 PASS / 0 FAIL。
- **状态**：✅ **已闭合**（2026-09-18，Phase 3 躯体期）
- **证据**：`services/java/body-service/src/main/java/com/agent/body/{store,service,client,controller}/`；
  `pom.xml` 已引入 `spring-boot-starter-data-redis` / `postgresql` 驱动，`QdrantClient` 直连 Qdrant REST API。
- 备注：原台账描述为「本地文件检索」，与当时实现（纯内存）不符（见 §4.2）；现已由真实三层存储取代。

- **证据**：`services/python/nlp-service/app/embedding.py:1,95-123`；`app/main.py:3`；

### 4.8 未映射路由返回 500 而非 404（2026-09-18 前端联通验证**发现并已闭合** ✅）

| 项 | 内容 |
|---|---|
| 现象 | 请求任何**未实现**的路由（如 `GET /api/body/definitely-not-a-route`）返回 `500 AGENT_INTERNAL_ERROR`，而非 `404`；方法不匹配、媒体类型不支持的场景同样落入兜底 500 |
| 根因 | 三个 Java 服务（`body-service` / `sense-service` / `session-manager`）的 `GlobalExceptionHandler` 只有「业务异常 / 参数异常 / 兜底 Exception」三档，Spring 路由层抛出的 `NoResourceFoundException` / `NoHandlerFoundException` / `HttpRequestMethodNotSupportedException` / `HttpMediaTypeNotSupportedException` 无对应处理器，全部落进兜底 `Exception` 分支 |

| 影响 | 误导排障方向（把拼错的 URL 当成服务故障）；正常链路不受影响 |
| 修复 | ① 三服务 `GlobalExceptionHandler` 新增 404/405/415 映射；② `ErrorCode` 补 `AGENT_METHOD_NOT_ALLOWED`；③ 三服务各补 `GlobalExceptionHandlerTest`（body 6 项 / sense 5 项 / session 5 项） |
