08 · 数据存储与归档¶

目标读者：需要理解「数据存在哪、什么结构、怎么降级、怎么备份恢复」的开发者。 本文是开发视角的存储总纲；逐字段的 DDL 与键设计在仓库 db/ 目录（结构文档 + 运行态快照），两者同步维护。

一、存储版图（哪个服务把数据放在哪）¶

服务 存储 内容 生命周期
gateway-service 无 纯路由/鉴权转发 —
session-manager Redis 会话哈希 session:{id} + 消息列表 session:{id}:messages TTL 2h，不持久
sense-service MinIO / 本地目录 采集暂存批（staging/{tenant}/{status}/batch-*） 采集→质检→消费→清理，短命
sense-service 内存（有界 500 条） 死信队列（重试耗尽的采集失败记录） 重启清空
body-service PostgreSQL（冷层真相源） knowledge_document / knowledge_chunk 元数据与正文 长期
body-service Qdrant（向量层） lifeform_knowledge 集合，point id = chunk_id 长期（可由 PG + 重建恢复）
body-service Redis（热层缓存） 检索结果缓存 knowledge:search:* + 访问计数 knowledge:access:* TTL 1h / 计数长期
nlp-service / wp-bff 无 无状态计算与代理 —

真相链：正文与元数据的真相在 PostgreSQL；向量的真相在 Qdrant（id 与 PG chunk 一一对应）；Redis 一律可清空重建；暂存区消费完即清理。因此备份恢复只需 PG + Qdrant 两份。

二、分层存储路由（body-service，R3-01）¶

TierRouter 依据热度决定读缓存还是回源：

hotness = (1 + ln(1 + 访问次数)) × 0.5^(age / 半衰期)
半衰期 3600s · hot ≥ 2.0 → HOT（Redis 缓存优先）· warm ≥ 1.0 → WARM · 其余 → COLD（直连 PG+Qdrant）

三个阈值均可配（app.body.tier.*）。分层是读取路由，不是物理搬移——数据始终以 PG 为真相，Redis 只是加速层。

三、降级不变量（存储不可用时）¶

故障 行为 可见性
PG 不可用 回落 InMemoryMetadataStore（元数据内存态），恢复后不自动回灌 启动告警 + health 标注
Redis 不可用 绕过缓存直连 Qdrant cache_backend=unavailable，命中率不虚增
Qdrant / 嵌入不可用 检索失败 AGENT_UPSTREAM_UNAVAILABLE（检索是 Must 项，不返回假结果）
MinIO 不可用 暂存降级本地 data/sense-staging/ warn 日志 + 引用格式变为本地路径
会话 Redis 不可用 会话创建失败 会话是 Must 项，不静默降级

四、db/ 目录（结构归档 + 运行态快照）¶

仓库根 db/ 是存储结构与数据的归档层，与代码的同步约定：

db/
├── README.md               总览：介质清单、分层路由、恢复指引、维护约定
├── postgres/schema.sql     可执行 DDL（与 PgMetadataStore 内嵌 DDL 同源，幂等）
├── postgres/schema.md      表结构说明（字段/索引/状态机/写入方）
├── redis/keyspace.md       键空间设计（4 类键：类型/写入方/TTL）
├── qdrant/collection.md    集合参数（768 维 Cosine / HNSW / payload 约定）
├── minio/staging.md        暂存双后端与对象键约定 + 死信队列说明
└── snapshots/              运行态真实数据导出（时间戳命名，只增不改）
    ├── postgres-schema.sql / postgres-data.sql
    ├── redis-keys.json     （导出脚本：scripts/export-redis-snapshot.py）
    ├── qdrant-collection.json / qdrant-points.json
    └── kafka-topics.txt

维护约定： 1. 改存储结构（DDL / 键设计 / 集合参数）→ 必须同步 db/ 对应文档 + schema.sql，并在本文 §七登记。 2. Java 侧 DDL（PgMetadataStore 内嵌常量）与 db/postgres/schema.sql 是同源双写：改一边必须改另一边（待引入 Flyway 后收敛为单源）。 3. 快照含租户数据（default / tenant-b），归档行为本身无害，但对外分享仓库前需确认。

五、恢复指引（速查）¶

docker compose up -d postgres redis qdrant minio kafka
docker exec -i lifeform-postgres psql -U agent -d lifeform < db/snapshots/postgres-schema.sql
docker exec -i lifeform-postgres psql -U agent -d lifeform < db/snapshots/postgres-data.sql
# Qdrant：集合由 body-service ensureCollection 自举；points 从 qdrant-points.json POST 回灌
# Redis / Kafka：无需恢复（会话自然过期、topic 自动创建）

完整步骤与注意事项见 db/README.md。
