# Java 服务源码说明文档

> 目标读者：接手本项目开发的工程师、需要快速定位改动点的维护者、代码评审人。
> 覆盖范围：`services/java/` 下 5 个 Maven 模块的**全部 193 个 Java 源文件**（103 手写 + 90 protoc 生成），逐文件说明其职责、关键成员与协作关系。
> 最后更新：2026-09-18（对应提交 `efb1273`；2026-09-18 复审后回填 body-service 与 wp-bff 计数）

## 这套文档解决什么问题

项目采用「人体生命体」隐喻做分层，模块名（感官 / 躯体 / 神经）与业务语义不是一一对应的字面关系，
新接手时容易出现「知道文件叫什么、不知道它在链路里干什么」的问题。本文档按**模块 → 包 → 文件**逐层展开，
每个文件给出职责、关键成员、上下游协作与对应需求编号（如 `R2-01`），便于从任意一个文件反查完整调用链。

## 阅读约定

- **需求编号**：`R0-xx` / `R1-xx` 为 Phase 0/1 需求，`R2-xx` 为 Phase 2 感官期需求，
  `R3-xx` 为 Phase 3 躯体期需求，`R-Cxx` 为终端线（Console / 工作平台）相关需求。
  编号定义在项目外的设计文档中：`…\AI知识库\任务指挥中心知识库\核心知识\AGENT_CONTEXT\`。
- **`proto-contracts` 的 90 个文件不在本文档逐文件展开**：它们 100% 由 `protoc` 生成，逐个人工描述没有信息增量；
  该模块改为按「契约 → 生成产物」维度说明，见 02 篇。
- **测试文件同样纳入本文档**：项目约定测试是回归防线（尤其 `HttpClientsTest`、`OutboundHttpTest` 是对
  已修复缺陷的守卫），测试类的意图描述与主代码同等重要。

## 维护约定

新增或删除 Java 文件后，请同步更新对应模块的文档，并遵守：

1. **文件清单表必须与代码一致** —— 清单表是「文件是否存在」的唯一索引，缺失会导致后来者找不到代码。
   改完用校验脚本自查（新增/删除 Java 文件后必跑）：

   ```bash
   cd <repo>
   python scripts/java-doc-coverage.py          # 逐模块覆盖率；有缺口时退出码 1（可用于 CI）
   python scripts/java-doc-coverage.py --list   # 额外列出已覆盖文件
   ```

   脚本按「源文件 basename 是否出现在文档中」判定覆盖，因此清单表里请保留带 `.java` 后缀的完整文件名。

2. **改动 `.md` 后需重新生成 HTML 镜像**（若需要网页版阅读）：

   ```bash
   cd <repo>
   E:/software/anaconda3/python.exe scripts/md2html-report.py --all "docs/java-services"
   ```

   必须使用 **anaconda Python** —— WorkBuddy 托管 Python 未安装 `markdown` 包。
   脚本的 `--all` 模式会自动排除 `README.md`（索引无需网页版）。

3. **本文档描述「设计意图」，不复制实现细节** —— 方法体逐行逻辑应以代码为准，
   文档只回答「这个文件为什么存在、它在链路的哪个位置」。
