二、逐条详情¶

DEBT-001 · body-service 检索为内存实现¶

  • 简化实现：BodyStore 用 ConcurrentHashMap<String, List<StoredChunk>> 按租户存切片； 检索打分是「整串包含 = 1.0，否则按查询字符在正文中的命中率」——纯内存、无持久化、无语义相似度。
  • 正式目标：Qdrant 向量检索。docker-compose.yml 已定义 qdrant 服务（端口 6333/6334）， 但当前没有任何服务调用它。
  • 触发点：VS3 完成（Phase 3，当前冻结）
  • 状态：🔴 未闭合
  • 证据：services/java/body-service/src/main/java/com/agent/body/store/BodyStore.java:9,22-48； 全仓无 qdrant 客户端依赖。
  • ⚠️ 台账原文描述为「本地文件检索」，与实际不符 —— 实际连文件都没落盘（见 §4.2）。

DEBT-002 · 回答生成为模板拼接¶

  • 简化实现：SessionController.buildAnswer() 把检索到的首条切片截前 240 字， 套进固定句式「根据知识库《X》检索结果：…」；无检索结果时返回固定致歉文案。
  • 正式目标：LLM 生成
  • 触发点：VS2 完成
  • 状态：🟡 未闭合
  • 证据：services/java/session-manager/src/main/java/com/agent/session/controller/SessionController.java:132-138； 债务标记在 proto/brain/v1/brain.proto:1。
  • 备注：台账原文把模块记为「大脑」，实际代码落在 session-manager（大脑期尚未开工）。

DEBT-003 · 会话存储 —— 已闭合 ✅¶

  • 原简化实现：会话与消息存进程内存 Map。
  • 当前实况：已改为真实 Redis。session-manager 依赖 spring-boot-starter-data-redis， application.yml 配置 ${REDIS_HOST:127.0.0.1}:${REDIS_PORT:6379}， SessionController 全程使用 StringRedisTemplate（Hash 存会话元数据 + List 存消息，2h TTL）。
  • 关闭依据：Redis 客户端与配置均真实存在，且会话写入/读取/删除全走 Redis （SessionController.java:10,22,45-51,102,112-117,126）。
  • 状态：✅ 已闭合（2026-09-17 核实）
  • ⚠️ 但 proto 源与两处生成物的注释仍写着旧实现（见 §4.3）。

DEBT-005 · 网关为最小 JWT¶

  • 简化实现：JwtService 使用 io.jsonwebtoken.security.Keys.hmacShaKeyFor() 做对称 HMAC 签发验签， 无签发方/密钥轮转/OIDC 发现端点。
  • 正式目标：OAuth2 / OIDC
  • 触发点：P7（见《D5-3-安全演进路径》）
  • 状态：🟡 未闭合（触发点未到）

DEBT-007 · L0 意图模型为统计分类器（非 BERT）¶
