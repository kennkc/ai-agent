二、逐条详情¶

DEBT-001 · body-service 检索为内存实现 —— 已闭合 ✅¶

  • 原简化实现：BodyStore 用 ConcurrentHashMap<String, List<StoredChunk>> 按租户存切片； 检索打分是「整串包含 = 1.0，否则按查询字符在正文中的命中率」——纯内存、无持久化、无语义相似度。
  • 正式目标：Qdrant 向量检索。docker-compose.yml 已定义 qdrant 服务（端口 6333/6334）， 但当时没有任何服务调用它。
  • 当前实况（Phase 3，2026-09-18）：body-service 整体重写为持久化知识管道：
  • 冷层真相源 PgMetadataStore（PostgreSQL）· 温层向量 QdrantClient（集合 lifeform_knowledge）· 热层缓存 HotCacheStore（Redis，租户前缀指纹）；
  • 统一门面 StorageFacade + 热度分层 TierRouter（阈值可配）；
  • 入库 IngestService（分块 → 嵌入 → 向量入库）、检索 RetrievalService（缓存优先 → 向量召回 → 重排）、 RagPipeline（检索增强生成）；
  • 旧的 BodyStore / BodyController / BodyStoreTest 已删除（被取代即销项）。
  • 关闭依据：端到端实测——文档入库后可被语义检索命中（语义相近可召回，非字符匹配）， 检索 P99 366ms（< 500ms 验收）、命中率 0.925、缓存命中率 0.45；租户隔离生效； 重入库幂等、删除无孤儿向量。验收脚本 35 项 PASS / 0 FAIL。
  • 状态：✅ 已闭合（2026-09-18，Phase 3 躯体期）
  • 证据：services/java/body-service/src/main/java/com/agent/body/{store,service,client,controller}/； pom.xml 已引入 spring-boot-starter-data-redis / postgresql 驱动，QdrantClient 直连 Qdrant REST API。
  • 备注：原台账描述为「本地文件检索」，与当时实现（纯内存）不符（见 §4.2）；现已由真实三层存储取代。

DEBT-010 · 嵌入走字符 n-gram 哈希后端（非 BGE-M3）¶

  • 简化实现：HashNgramEngine —— 字符 1/2/3-gram + 英文词元做 blake2b 哈希分桶（768 维）+ 亚线性 TF 加权 + L2 归一化。 纯本地、零依赖、跨进程确定性，但其相似度本质是「字面特征重叠」，不等价于语义相似度。
  • 正式目标：BAAI/bge-m3（sentence-transformers，1024 维）。
  • 触发点：安装 sentence-transformers + 下载 BGE-M3 权重（本机未装）。
  • 状态：🟡 未闭合（触发点未到）—— 但不构成 Phase 3 验收阻塞： R3-03 的验收口径是「嵌入延迟 P95 < 200ms；向量维度正确」，降级后端满足；且引擎链自动优先 BGE-M3， 装好即切换，无需改代码。
  • 证据：services/python/nlp-service/app/embedding.py:1,95-123；app/main.py:3； 切换后须重建 Qdrant 集合（维度 768→1024），见 QdrantClient.ensureCollection。
  • ⚠️ 切换影响面：换后端 = 换向量空间 → 必须全量重索引 + 评测回归（设计 §6 回归注意）。

DEBT-011 · 重排走词法覆盖率打分（非交叉编码器）¶

  • 简化实现：LexicalRerankerEngine —— 查询特征覆盖率 0.7 + 词元命中率 0.3，再乘长度惩罚（理想区间 120–640 字）。 与 DEBT-010 的哈希嵌入同源共享 _features，故降级链路上排序单调一致。
  • 正式目标：bge-reranker-v2-m3（CrossEncoder）。

  • 证据：services/python/nlp-service/app/reranker.py:1,76-107；app/main.py:4。
