判定标准是可执行的：把文档里的每个数字与描述，拿去和当前源码、实测输出对一遍。

3. 核查结论：5 类失效¶

3.1 门禁红灯：3 个新测试文件未登记（存在性失效）¶

java-doc-coverage.py 输出 103/106，未覆盖 3 个文件 —— 即最近三轮新增的 common/GlobalExceptionHandlerTest.java（body / sense / session 各一份）。 这与 docs/java-services/README.md §维护约定「新增/删除 Java 文件后必须登记」直接冲突， 且该门禁是会阻断 CI 的（非零退出）。

3.3 最新功能的逻辑说明缺失（内容失效）¶

本轮（bce7921）修的路由层错误语义，是三个服务共同的横切约定， 但作为横切约定权威文档的 07-运行时配置与横切约定：

  • 错误码表 没有 AGENT_METHOD_NOT_ALLOWED（405）——新增的错误码没进表；
  • 完全没有描述「未映射路由 → 404 / 方法不支持 → 405 / 媒体类型不支持 → 415」这套分流， 连一节都没有；
  • 仍写「session-manager 与 sense-service 各有一份 ErrorCode」，而实际已是三份。

也就是说：代码改了、测试补了、台账登记了，但"给人读的逻辑说明"没有跟上。

3.4 端点清单写错路径（可用性失效）¶
