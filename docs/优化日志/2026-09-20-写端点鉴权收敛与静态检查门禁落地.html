严重度 问题 证据

2. 修复 1：写端点鉴权收敛到路由层唯一入口¶

改动（services/node/wp-bff/server.js）：

  • 新增 WRITE_METHODS = {POST, PUT, PATCH, DELETE} 常量
  • 在路由分发之前统一执行 authorizeControl（来源白名单 + 控制令牌双校验）
  • 鉴权先于路由匹配：未带令牌访问任意写路径一律 401，不泄露路由是否存在
  • 读方法（GET）保持开放，仅受 CORS 白名单约束

为什么改路由层而不是逐个 handler：19 个写端点逐个补校验，下一次新增端点仍可能漏； 收敛到唯一入口后，"漏加鉴权"在结构上不可能发生。

回归用例（test/server.test.js 新增 3 条，测试总数 103 → 106）：

  1. 路由层统一鉴权：未带令牌访问不存在的写路径 → 401（而非 404）
  2. 代表性写端点（12 条路径）未带令牌 → 全部 401 + AGENT_UNAUTHORIZED
  3. 来源越权 → 403 + AGENT_FORBIDDEN

3. 修复 2：用量聚合的时区显式化¶

改动（app/token_usage.py）：

  • 引入 _today()，默认按 UTC 取日；可通过 TOKEN_USAGE_TIMEZONE（IANA 名）切换业务时区
  • 时区数据缺失时回落 UTC 并告警，不静默使用进程本地时区
  • 替换 2 处裸 date.today()（usage_summary 窗口起点、_row 的 bucket_date 默认值）

4. 修复 3：静态检查门禁落地（223 → 0）¶

新增 services/python/pyproject.toml：固定规则集（E/W/F/I/UP/B/SIM/RUF/BLE/ISC）+ 中文项目必要的忽略项：

  • RUF001/RUF002/RUF003：全角标点的歧义 Unicode 规则对中文注释/文档字符串是误报（占原报错 90% 以上）
  • E501：注释中的表格与说明需超长行

修复：

  • 自动修复 220 项（未使用导入、导入排序、无用 noqa 等）
  • 手工修复 F601（intent/corpus.py 重复字典键）、F402/F811（semantic_cache.py 中 field 遮蔽与重定义）、ISC004（7 处 SQL 跨行隐式拼接改为显式写法）
  • 为 7 处有意的宽泛捕获补 # noqa: BLE001 - <理由>（降级路径，均带日志）

CI（.gitlab-ci.yml）：pip install ruff → pip install ruff==0.16.8，消除版本漂移。

5. 过程中的一个坑（值得记录）¶

执行 ruff --fix --unsafe-fixes 后，UP017 规则把 timezone.utc 改写为 datetime.UTC， 而本机 Python 是 3.10（datetime.UTC 需 3.11+）→ 5 个测试模块直接收集失败。

处置：

  1. 回滚为 timezone.utc（兼容 3.10 与 CI 的 3.12）
  2. pyproject.toml 的 target-version 由 py312 改为 py310（按兼容下限约束，避免再次生成 3.11+ 专有语法）

教训：unsafe-fixes 必须紧跟一次完整测试，否则会把"语法现代化"变成"运行时不兼容"。
