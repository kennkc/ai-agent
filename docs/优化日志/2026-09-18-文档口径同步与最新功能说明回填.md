## 3. 核查结论：5 类失效

### 3.1 门禁红灯：3 个新测试文件未登记（**存在性**失效）

`java-doc-coverage.py` 输出 **103/106**，未覆盖 3 个文件 —— 即最近三轮新增的
`common/GlobalExceptionHandlerTest.java`（body / sense / session 各一份）。
这与 `docs/java-services/README.md` §维护约定「新增/删除 Java 文件后必须登记」直接冲突，
且该门禁是**会阻断 CI 的**（非零退出）。

### 3.2 基线数字静默过期（**准确性**失效，最严重）

门禁只查「文件有没有登记」，**不查「登记的数字对不对」**。于是同一批提交里：

| 位置 | 文档写的 | 实测 |
|---|---|---|
| `04-session-manager` 头部 / §4.14 | 4 个测试 / 4 个类 · 10 个用例 | **5 个 / 5 个类 · 15 个用例** |
| `05-sense-service` 头部 / §4.2 / §8 | 8 个测试 / 48 个用例 | **9 个 / 53 个用例** |
| `06-body-service` 头部 / §3.2 | 9 个测试（886 行）/ 54 个用例 | **10 个（975 行）/ 60 个用例** |
| `项目进度总览` §3.1 / §四 | 103 源文件 / Java 114 | **106 源文件 / Java 130** |
| `功能开发流程` §四 | Java 61 + Python 19 + wp-bff 14 | **Java 130 + Python 52 + wp-bff 29** |

数量级已经错到「6 个功能点之前的旧口径」。**这类漂移不会触发任何告警**。

### 3.3 最新功能的逻辑说明缺失（**内容**失效）

本轮（`bce7921`）修的路由层错误语义，是**三个服务共同的横切约定**，
但作为横切约定权威文档的 `07-运行时配置与横切约定`：

- 错误码表 **没有 `AGENT_METHOD_NOT_ALLOWED`（405）**——新增的错误码没进表；
- **完全没有描述**「未映射路由 → 404 / 方法不支持 → 405 / 媒体类型不支持 → 415」这套分流，
  连一节都没有；
- 仍写「`session-manager` 与 `sense-service` 各有一份 `ErrorCode`」，而实际已是**三份**。

也就是说：**代码改了、测试补了、台账登记了，但"给人读的逻辑说明"没有跟上**。

### 3.4 端点清单写错路径（**可用性**失效）

`功能开发流程.md` §3.6 把 body-service 的 RAG 端点写成 `POST /api/body/rag` ——
该路径**没有任何控制器映射，照抄调用会得到 404**（正确是 `/api/body/rag/answer`）。
同一段还漏登记了 `/knowledge/batch`、`/retrieve/plan`、`/knowledge/reconcile` 三个端点，
入库链路漏了 `DocumentParser`（格式解析步，R3-02 的关键实现）。
文档教人怎么调接口，路径错了比没写更糟。

### 3.5 文档内部自相矛盾 + 环境口径过期

- `06-body-service` §3.1 表格写 `IngestService` 172 行 / `RetrievalService` 183 行，
  而 §4.3 / §4.4 正文标题写 152 / 154 —— **同一份文档里两个数**；
- `功能开发流程` §3.11 与 §五 仍写「生成 HTML **必须 anaconda Python**」，
  而 anaconda3 已于同日卸载，现口径是托管 Python + `PYTHONPATH` 指向 `pylibs`；
- `功能开发流程` 头部「代码基线 `a5e0cd5`」与 `项目进度总览` §5.1 三分支头，均已落后 5 个提交。

## 7. 结论

- **回答用户的问题：没有同步。** 而且不只是"落后一轮"——模块文档的基线数字整体停在
  **6 个功能点之前**的旧口径，最新一轮的路由层错误语义在**给读者看的文档里完全不存在**，
  还写了一处**照抄会 404** 的端点路径。
- **根因不是疏忽，是门禁只覆盖了一半**：`java-doc-coverage.py` 守住了「有没有登记」，
  没守住「登记的对不对」；于是红灯会亮（文件数），而数字错了不会亮。
- **本轮已把可核实的全部回填**，并把门禁复位到全绿（106/106 · 0 FAIL · 无 STALE）。
- 把这次性修复变成**结构性防线**的方案已登记（台账 §6 待办 17），与待办 16 建议合并实施。

> 口径提醒：**"门禁绿灯" ≠ "文档准确"**。存在性与准确性是两件事，
> 只要后者没有自动化，"文档已更新"这句话就仍需人工核实。
