生产加固与 Phase 6 前置设计冻结（2026-09-20）¶

范围：生产路由、模型配置 fail-closed、协作数据质量、前端覆盖率门禁、文档真相源、Phase 6 前置设计 结论：不启动 Phase 6 代码开发，先关闭当前最影响稳定交付的生产化缺口并冻结未来接口。

1. 本轮解决的问题¶

问题 修复前风险 本轮处置
生产环境没有正式 wp-bff 路由 前端只能依赖 Vite 开发代理 gateway-service 新增 /api/wp/** -> WP_BFF_URI；提供 Nginx 模板
模型配置 PG 失败仍内存成功 页面显示已保存，重启或换实例后配置消失 生产开关要求持久化；失败返回 503 AGENT_CONFIG_STORAGE_UNAVAILABLE
生产可自动生成本地主密钥 密钥生命周期不可控，环境迁移困难 MODEL_CONFIG_ALLOW_LOCAL_KEY_FILE=false 禁止文件回退
协作视图真实/占位字段混在一起 占位工件、验收门、吞吐量可能被误当真实 BFF 返回 data_quality，页面显示 Phase 6 占位提示
OpenAPI 字段漂移 契约写 msg_flow，实现对前端返回 messages 契约修正为 messages，并增加 data_quality
前端覆盖率只看报告不阻断 覆盖率下降不会导致 CI 失败 Vitest 设置行/语句 25%、函数 20%、分支 65% 门禁
进度文档可出现过期口径 planned 数量、分支拓扑、覆盖率可能与现实不一致 新增 scripts/doc-truth-check.py，CI 接入当前测试生成物
Phase 6 尚未开工但没有冻结接口 后续 DAG、状态机、工件语义可能返工 新增前置设计冻结稿，不写 Phase 6 代码

2.2 模型配置 fail-closed¶

新增环境变量：

变量 开发默认 生产要求
MODEL_CONFIG_ALLOW_LOCAL_KEY_FILE true false
MODEL_CONFIG_REQUIRE_PERSISTENCE false true

生产模式行为：

  • 新增、更新、删除 PG 失败均返回 503；
  • 不把内存写入伪装成持久化成功；
  • 缺少环境主密钥且禁止文件回退时，key_available=false；
  • status() 返回 persistence_required、key_available、key_source。

2.3 协作数据质量¶

BFF 返回：

{
  "data_quality": {
    "source": "collab-bus-heartbeat",
    "real_fields": ["domain_id", "progress", "agents.progress", "agents.state"],
    "synthetic_fields": ["artifacts", "gates", "agents.model", "p99_ms"],
    "note": "仅心跳聚合与成员状态为真实数据；其余待 Phase 6 接线。"
  }
}

协作页面在存在 synthetic fields 时显示告警，不允许把 Phase 6 占位数据当业务真相。

2.4 覆盖率与文档门禁¶

  • web/work-platform/vitest.config.ts：覆盖率阈值硬门禁。
  • scripts/doc-truth-check.py：
  • 计算 OpenAPI implemented / planned；
  • 检查分支拓扑、R-MC01-05 状态、生产路由、模型配置变量；
  • 优先读取当前前端 JUnit / coverage 生成物；
  • 拦截已废弃的“尚未提交”“30 planned”等表述。
  • GitHub Actions frontend job 在测试报告后执行文档真相源校验。
