8. 关键教训¶

"文档已更新"是一个需要分层回答的命题。

同一个仓库里，三个阶段的分级文档可以同时处于三种状态：

层 例子 本轮状态
阶段内模块文档 docs/java-services/04~07 ✅ 上轮刚回填，准确
项目级概览 docs/项目进度总览.md ✅ 上轮已改，准确
仓库最高层入口 README.md / PROGRESS.md ❌ 本轮才补齐

教训在于：沿着「模块文档 → 项目概览 → 仓库根 README」这条汇报链一路往下补细节时， 最顶层、最容易被人第一眼看到的入口反而最容易被跳过 —— 因为它"看起来不需要改"（没人去看它是否还写着三个月前的结论）。

推论：每次改动收尾时，先问一句"仓库 README 还成立吗"，再问子目录文档。
